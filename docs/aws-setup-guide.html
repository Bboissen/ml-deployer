AWS workspace: first-use guide

Run make in the repository folder and answer its questions in that terminal. It prepares the tools, saves your project file and offers native sign-in. This page only shows progress; it never logs in, deploys or changes anything.

No live readiness. Run make in the repository folder and open the address it prints to see which steps are done. Opened as a file, this page is a plain checklist.

JavaScript is off: readiness is not shown and both public and private variants are listed.

  1. Get the source and run make

    git clone https://github.com/Bboissen/ml-deployer.git
cd ml-deployer
make

    make downloads hash-pinned AWS CLI, OpenTofu, Python and Session Manager builds into the repository's ignored .tools/ folder (about 600 MB), then asks for your project settings. Keep the terminal open; Ctrl+C stops setup and this page. Rerunning make resumes.

    Laptop connected over SSH? Keep the repository on the server and run make there. It detects SSH and prints a tunnel command to run in a new laptop terminal outside SSH and the link to open in your laptop browser. Answer the questions in the SSH terminal.

    Ubuntu/Debian: if setup reports missing system packages, run ./workspace setup --system-packages (sudo installs curl, unzip, tar, dpkg), then make again. macOS: install the Command Line Tools when prompted. Supported: Linux with glibc (x86_64, arm64) and macOS (Intel, Apple Silicon).

  2. Describe your project

    Answer two questions in the terminal running make. It first signs you in to GitHub once (browser flow), then reads everything else from GitHub and your AWS profile and saves a validated private project file. Credentials are never typed here.

    You enterWhat to answer
    GitHub repositoryowner/name or its github.com URL.
    DatasetA file or folder on this machine, an s3:// prefix or a public HTTPS file.
    DerivedFrom
    Repository URL and branchGitHub: private repositories use the git@github.com: URL and a deploy key, public ones HTTPS; the default branch.
    Project nameThe repository name, lowercased (3 to 24 characters).
    AWS profile and regionAWS_PROFILE or your only console/SSO profile (asked only when there are several; a new one is named ml-deployer); us-east-1.
    Runjob mode: make setup then make train, at most 60 minutes, results from outputs/. Setup checks that your Makefile has both targets (runtime contract).

    No questions at all: make REPO=owner/name DATASET=/path/to/data. The default file is ~/aws-workspace/demo/project.json; choose another with make PROJECT=/path/project.json. Rerunning keeps existing values; edit the file to override any of them. Field reference: project configuration.

  3. Sign in to AWS

    make offers sign-in with the derived profile and opens the AWS browser flow. Over SSH it prints a link: open it on your laptop, finish signing in, then copy the authorization code AWS displays back into the waiting terminal prompt and press Enter. This repository never sees or stores a password or access key.

    ./workspace login --profile my-workspace --region us-east-1

    Add --method sso for IAM Identity Center and --remote when the browser is on another device. Static access keys are refused. A successful login does not prove permission to create infrastructure; Deploy checks that against its saved plans.

    ./workspace login runs native aws login with the project's pinned CLI, checks the profile for conflicting credentials, and verifies the resulting CLI and SDK identities. You can also run aws login --profile my-workspace --region us-east-1 --remote directly with a compatible CLI, then run ./workspace auth-check --profile my-workspace --region us-east-1.

    Browser shows “400 Bad Request”? Each sign-in link works once, for a few minutes, while the login command still waits. Press Ctrl+C, run the login again and use only the newly opened page.

  4. Connect GitHub

    Setup signs in once with the managed GitHub CLI and reads the repository, its visibility, default branch and Makefile targets (read-only).

    ./workspace github-login
    Public repository

    Deploy clones over HTTPS, for example https://github.com/owner/project.git; it needs no GitHub access on the machine.

    Private repository

    Setup picks the SSH URL, for example git@github.com:owner/project.git. You need admin permission on that repository: Deploy registers a read-only deploy key and stores its private half only in AWS Secrets Manager.

  5. Review and deploy

    The first command resolves your account, zone, repository commit, dataset bytes, machine size, price estimate, retained resources and lifetime into one scope, prints it with its hash, and asks once. Type deploy to launch exactly that scope; press Enter to stop with no cloud change.

    ./workspace ~/aws-workspace/demo/project.json
./workspace ~/aws-workspace/demo/project.json status --wait 30

    For automation, rerun with --authorization "approve scope HASH" where HASH is the 16-character scope hash the review printed. Nothing launches without the typed confirmation or that hash. A changed file or source needs a new review.

  6. Find your outputs and confirm cleanup

    The outcome lists infrastructure, setup, job, output persistence and cleanup separately. compute cleanup: success with outputs verified after compute deletion: True means the machine, disk and network interface are gone and your results are still readable at the printed s3://…/output/ prefix.

    ./workspace ~/aws-workspace/demo/project.json logs

    Kept on purpose: the dataset and output bucket, the separate state bucket, the no-ingress network, IAM boundaries and the expiry guard. They can keep costing money; deleting them is a separate reviewed decision. A second Deploy with the same data reuses the retained versions without uploading again.

Something broke

Tools half installed or failing: stop the running guide with Ctrl+C. make clean removes interrupted builds and keeps installed tools. make fclean also removes installed managed tools, the project settings file and its AWS sign-in; the next make reinstalls them and asks again. make re performs that full clean and restarts setup. The GitHub login, datasets, state and evidence are preserved.

make re
./workspace doctor ~/aws-workspace/demo/project.json --debug

A Deploy was interrupted: ./workspace project.json resume reconciles owned resources and never repeats a launch; cancel removes the owned compute.

The launcher itself is broken: git checkout -- workspace scripts restores the tracked files.
